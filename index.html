Rename Zoom recordings and upload directly to Dropbox

How to use this app

What it does

After a virtual ABC session, Zoom saves recordings as generic numbered files (video1.mp4, video2.mp4 …). This app renames each file to the ABC naming convention and uploads them directly to the lab's Dropbox — no Python, no installation, works in any browser on any computer.

Step-by-step

  1. Connect to Dropbox — sign in with your lab Dropbox account. You only need to do this once per browser session.
  2. Participant ID — enter the 4-digit ABC number (e.g. 1529). No need to type "ABC".
  3. Session Date — pick the date the session was recorded.
  4. Participant Sex — select Female or Male. This only affects the PCR filename.
  5. Load Recording Folder — click the folder area and navigate into the inner Zoom folder (the one that contains video1.mp4, video2.mp4, etc.), then click Select Folder. You can also drag-and-drop the folder.
  6. Review task names — the 8 tasks are pre-filled in the standard order. Edit any name if a session ran tasks in a different order.
  7. Check the preview — confirm the filenames look correct before uploading.
  8. Upload to Dropbox — click the green button. A progress bar tracks each file. When all bars are green, the files are in Dropbox under ABC Virtual Testing Behavioral Data / ABC####/.

File naming format

Each file is renamed to: ABC####_TaskName_M.D.YY.mp4
Example: ABC1529_CookieTheft_3.5.26.mp4

How it knows which video is which task

Zoom names each recording segment with a number prefix — video1021779609.mp4, video2021779609.mp4, etc. The first digit is the task number. The app reads that digit and maps it to the task in the standard order above. If a task ran in a different slot, you can reassign it in the Task Names section before uploading.

🔒 Privacy & data security

Because these recordings contain protected participant data, it is important to understand exactly where files go when you use this app.

  • Videos never leave your computer except to go to Dropbox. When you select a folder, the files are read into your browser's local memory only. They are sent directly from your browser to Dropbox's servers — no intermediate stop.
  • GitHub never sees the video files. The GitHub server only delivers the app's HTML/JavaScript code when you first open the page. Once loaded, GitHub is completely out of the picture.
  • No backend server exists. This app has no server of its own. It is a static webpage — all processing happens locally in your browser. There is nowhere else for data to be stored or logged.
  • No analytics or tracking. The app contains no Google Analytics, error-reporting services, or any third-party scripts. The only external connections made are to dropbox.com for authentication and upload.
  • Your Dropbox login token is temporary. The access token used to authenticate with Dropbox is stored only in your browser's session memory and is automatically erased when you close the tab.

The data flow is equivalent to manually dragging files into the Dropbox desktop app — participant recordings go only to the lab's designated Dropbox folder and nowhere else. The full source code is publicly auditable at github.com/chandlernichols41/Virtual_testing_sorter.

⚠️ This app requires all 8 task videos to be present. It identifies each task by the video's number in the Zoom recording order. If any videos are missing, the remaining files may be assigned to the wrong task. Do not use this app for incomplete sessions — rename those files manually.
⚙️ One-time setup required This tool needs a Dropbox App Key before it can authenticate. The Dropbox App Key placeholder was not replaced during deployment. Check that the DROPBOX_APP_KEY secret is set in your repo (Settings → Secrets → Actions) and re-run the workflow.
